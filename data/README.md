# Input data

The Zenodo deposit for this study contains **raw UAV photographs only**. Nothing else — no
orthomosaics, no canopy masks, no digital surface models, no city-wide mask.

**Zenodo deposit:** UAV Imagery — https://doi.org/10.5281/zenodo.22141709

## What is in the deposit

| Folder | Description |
| --- | --- |
| `Field1_raw_images/`, `Field2_raw_images/`, `Field3_raw_images/` | Raw geotagged UAV photographs (JPEG, embedded GPS EXIF) for the three survey fields, several hundred images per field, as captured on the 15 and 25 January 2026 flights |

## Building the pipeline inputs yourself

This repository does not perform photogrammetry. To get from raw photographs to the files the
code expects, run each field's photo set through photogrammetry software such as Agisoft
Metashape, Pix4Dmapper, or the open-source OpenDroneMap / WebODM, then export:

| File the code expects | Export it as |
| --- | --- |
| `Field1_ortho.tif`, `Field2_ortho.tif`, `Field3_ortho.tif` | Orthomosaic, EPSG:32645, RGB |
| `Field1_dsm.tif`, `Field2_dsm.tif`, `Field3_dsm.tif` | Digital surface model, same grid as the orthomosaic |

Both products come out of the same photogrammetry run on the same photo set, so producing the
orthomosaic and the DSM together costs no extra field work.

Reference canopy masks and the city-wide canopy mask are not part of this deposit. Canopy
masks can be regenerated by running the rebuilt orthomosaics through the published segmentation
weights (see below); there is no ground truth left to score that output against, so the
F1 / IoU figures in the paper cannot be independently rechecked. The city-wide mask depends on
PlanetScope imagery, which was never redistributable regardless of this decision.

## Trained weights, in place of the training annotations

The manual crown annotations used to train the segmentation model are not released. Published
weights let step 1 be skipped entirely:

    https://huggingface.co/Sabbir12345/P6_S4_SegFormer_RGBExG_100ep

Point `segmentation.checkpoint` in `config.yaml` at the downloaded file and start at step 2
once you have built the orthomosaics above.

## Not redistributable, and freely available elsewhere

`planetscope_superdove.tif` is not included. The PlanetScope SuperDove imagery was obtained
under the Planet Education and Research Program and cannot be redistributed. Researchers can
request equivalent imagery directly from Planet Labs PBC.

`alos_palsar_dem.tif` is not included either, because it is openly available. Download the
12.5 m ALOS PALSAR radiometrically terrain-corrected product covering Pabna from the Alaska
Satellite Facility and save it under this name.

## What runs with which files

| Step | Needs | Reproducible from this deposit |
| --- | --- | --- |
| 0 | field DSMs, terrain DEM | Only after you build the DSMs yourself |
| 1 | `uav_tiles/` annotations | No, not released; use the published weights instead |
| 2 | field orthomosaics, checkpoint | Only after you build the orthomosaics yourself |
| 3 | field canopy masks or step 2 output; CHM for heights | Only after the steps above |
| 4 | satellite image, field masks | No, imagery not redistributable |
| 5 | crown tables from step 3, including height; city-wide canopy mask | Only after steps 0-3 |
| 6 | ward boundaries, city-wide canopy mask | No, needs step 4's output |

Every step can technically be rerun starting from what is in this deposit, but steps 0 and 2
require you to redo the photogrammetry first, and step 4 requires imagery this deposit was
never allowed to include. There is no ground truth left anywhere to check segmentation
accuracy against, so treat any rerun's F1/IoU as a new result, not a check on Table 2.

## Coordinate reference system

All rasters are expected in EPSG:32645 (UTM zone 45N). The steps read the transform and CRS
from each file, so areas are computed in square metres without further reprojection. The
terrain DEM is the one exception: step 0 resamples it onto each DSM grid, so it may arrive in
its native CRS. If your other files use a different CRS, set `project.crs` in `config.yaml`
and reproject the inputs to match before running.
